# screw

## What This Is

A parametric generator for threaded fasteners — hex bolts and screws, hex nuts, and (second
release) socket head cap screws. Set the parameters, get a live 3D preview, the numbers you
would measure on the real part, and an STL or STEP download — from a web UI, an HTTP API
and a CLI, all driven by one parameter model. The sibling of `spur`
(`/Users/halfb00t/git/halfb00t/spur`, a parametric involute spur gear generator, at commit
`ec195fb`): same stack, same approach, same working rules, separate repo and separate
product. spur stays a gear generator; screw is fasteners only — decided 2026-10-05 in
spur's `/gsd-new-milestone` session over the alternative of making spur a "parts
generator".

For whom: the owner printing fasteners on an FDM printer; makers and hobbyists with a
printer who today take OpenSCAD/Thingiverse threads with no guarantee a pair mates; CAD
users who need a fastener as a precise STEP solid with a real thread, where McMaster /
TraceParts STEP files carry cosmetic threads or none.

## Core Value

A bolt and a nut generated by this tool actually thread together when printed, and every
number it prints is one someone can cut metal to — computed honestly from explicit
millimetres or a cited ISO row, or reported as a warning and no number. Everything else
(the UI, the API, the CLI, the presets) exists to get parameters in and a trustworthy
mating pair out.

## Requirements

### Validated

- ✓ Parity across UI, API and CLI is proven model-driven by one test over the registry
      (`tests/test_parity.py`), not by hand — Phase 1, on the skeleton `bolt` kind; a
      planted CLI flag, an extra info query field and an `info.length` read in `app.js`
      each turn it red.
- ✓ CAD builds run in worker processes off the event loop; admission control (bounded
      queue, `503` + `Retry-After`) lives in the web layer only — Phase 1 (ported pool with
      the D-16 same-slot guard; every bound is INTERIM until the Phase 7 re-sweep).
- ✓ Thread generation's cost is measured by a pre-registered spike before any field
      exists — Phase 2 (campaign `2026-10-08-a`, L11: sewn twist-section at K = 3; precise
      `BRepGProp` volumes gated at `T_gate` 9e-05; construction cap 250 turns at every size;
      bytes caps M8–M20 under the INTERIM 64 MiB budget; seconds caps not established because
      the grid run was non-decisive under owner ruling R4, and nothing was re-run toward a
      value).

### Active

All hypotheses until shipped and validated. Grouped by the owner's decisions of
2026-10-05; the first release is the mating-pair cut.

**Threads and mating (the product)**
- [ ] Real helical ISO metric threads (ISO 68-1 profile) on every threaded part; cosmetic
      or unthreaded bodies are not the product. Whether an `unthreaded` flag exists at all
      is a requirements question; if it does, it defaults off.
- [ ] A bolt and a nut from this tool, printed on an FDM printer at the chosen clearance,
      thread together by hand; a kernel-level interference check proves the pair before any
      printer does. Phase 2 measured the check falsifiable on both hands at every size except
      M18, where every proof clearance is excluded (L11 escape clause); the roadmap is
      revised before Phase 5 is planned.
- [ ] One `clearance` field, carried by the **nut** (its thread grows inward); the bolt is
      built to nominal so it mates a bought nut. The default value comes from the thread
      spike and a printed test, never from a guess.
- [ ] Left-hand threads via a boolean field, default right-hand.
- [ ] Thread length on bolts via one `thread_length` field: the ISO 4017 preset sets it to
      the full length, the ISO 4014 preset sets `b` from the table; the user may edit it.

**Presets and tables**
- [ ] ISO tables as presets, explicit millimetres as truth: a size picker ("M6 × 20,
      ISO 4017") fills the mm fields from a cited table; the part is always built from the
      mm fields in the shareable link, and the user can edit any of them.
- [ ] Every table row carries its standard and clause and has one verification test; a row
      without a cited source does not ship.
- [ ] Size range M2–M20 (ISO 261 preferred sizes) for every table in v1.
- [ ] ISO 965 tolerance classes 6g / 6H reported as min/max numbers on the info panel from
      a cited table; geometry is nominal plus clearance, not toleranced.

**Fastener types**
- [ ] v1 (first release): hex head bolt/screw — ISO 4014 (partial thread) and ISO 4017
      (full thread); hex nut — ISO 4032; proven as a mating pair.
- [ ] v2: socket head cap screw — ISO 4762, on the proven path. Priced at one more phase:
      cylindrical head + hex socket, the 4762 table (~13 rows × tests), its own build-time
      measurement; the thread is shared.

**Three front ends, one model**
- [ ] Every fastener type ships on UI, API and CLI from the one parameter model, with its
      tests, in the same change; the Phase 1 parity test covers each new `KINDS` entry
      without an edit.
- [ ] Every number on the info panel is traceable to an explicit mm field or to a cited ISO
      row with a test; where a number cannot be computed honestly the tool shows a warning
      and no number.

**Operability (inherited shape)**
- [ ] Every allowed configuration builds inside a measured per-build timeout, with the bound
      that keeps it there recorded (the Phase 2 spike left every seconds cap "not
      established"; Phase 3 caps on construction and bytes until a decisive run exists).

### Out of Scope

- **Self-tapping, wood and sheet-metal screws** — a different thread form (sharp, tapered,
  no mating nut): a separate geometry problem, not a variant of a machine screw, and
  nothing to prove a pair against. Out of v1; not a deferred requirement.
- **Head markings** (strength grade, manufacturer) — cosmetic text on the head. Printed
  plastic has no strength grade; text in the kernel means fonts, a separate problem. Out.
- **UNC / UNF and any non-ISO thread form** — ISO metric only in v1 (ISO 68-1 profile,
  ISO 261/262 sizes).
- **Countersunk screws, set screws, washers** — not in the first two releases; revisit once
  socket cap has shipped on the proven path.
- **Modelling tolerance classes as geometry** — conflicts with "explicit millimetres are
  truth" and with the clearance field; tolerances are reported numbers only.
- **Sizes below M2 or above M20** — M1.6 does not print; M24+ means long thread builds
  against the timeout. Every row is a test; the range grows when someone needs it.
- **Extracting the shared infrastructure into a package** — deferred until the first time
  a fix has to land in both repos (`docs/tech_debt/active/2026-10-05-shared-infra-extraction.md`).

**Read before planning (spur):** `CLAUDE.md`, `docs/CODING_VALUES.md`,
`docs/HOW_TO_DEVELOP.md`, `docs/architecture/decision_log.md`, `.planning/RETROSPECTIVE.md`.
Lessons from three spur milestones that apply here unchanged:
- Measure before knobs: every runtime bound cites the bench run that set it; a gate's
  offer is a probe's number, never a round figure.
- A bar at the instrument's noise floor is not a bar; measure the harness first.
- Verify a phase's premise with a live read before planning it.
- Spike before field: `HEX_CELL_CAP`, the tip-chamfer boundary and `ROOT_CONTACT` were
  all measured by a throwaway probe before any schema field existed.
- Hooks that take minutes need commits that wait minutes; `gsd_run query commit`'s 30 s
  timeout versus a long `make verify` hook cost spur every close-out commit.
- Write a milestone's success metric about the state at kickoff, or its own discoveries
  fail it.
- Triage review findings before the close or carry an explicit count forward.
- Pre-registered measurement: method, predictions and escape clause committed before the
  first run.

**Research items (for the research step, not the owner):**
- `cq_warehouse.fastener` (CadQuery library: ISO/ASME tables, real threads; unverified):
  dependency, reference, or the thing to beat? Licence, thread build times, whether its
  tables cite clauses.
- Thread generation in OCCT: helix sweep vs `cq_warehouse`'s approach vs anything newer;
  build time vs thread length and diameter; STL triangle count and export size for helical
  surfaces (spur's gzip and export-cost harnesses re-measured here).
- FDM practice for printed mating threads: typical radial clearance, which part carries it,
  minimum printable pitch.
- Table sources: ISO 68-1, 261, 262, 4014, 4017, 4032, 4762, 965 (tolerances; the brief
  wrote 4759 — confirm which); the DIN numbers hobbyists search for (933, 931, 912, 934)
  and how they map.
- STEP convention for threads: modelled vs cosmetic; what downstream CAD does with a
  modelled thread.
- How a mating pair is proven in the kernel (interference volume with clearance) and what
  it costs.

**One caveat on the brief's own claims:** the ISO standard numbers are from memory
(68-1, 261/262, 4014/4017, 4032, 4762, 965/4759); research must confirm each before a
table cites it. `cq_warehouse.fastener` is likewise unverified.

**Known risks:**
- Thread build time against a per-build timeout is unmeasured. Spike first, write the bound
  as a measured constant, then add the field.
- Table liability: every ISO row shipped is a claim; one verification test per row, source
  cited, or the row does not ship.
- Helical STL size: triangle counts and export cost will be far above spur's; re-measure
  before setting any cache or gzip number.
- The mating proof: a pair that passes a kernel check and fails on a printer is the failure
  mode the first success criterion is designed against.

## Constraints

- **Tech stack**: Python 3.12 only, CadQuery / OpenCascade, FastAPI + Pydantic v2 +
  uvicorn, argparse, vanilla JS + vendored three.js, pytest, Docker + compose
  (`linux/amd64` + `linux/arm64`), GitHub Actions — `L01`; `cadquery-ocp` publishes wheels
  for nothing newer than 3.12.
- **Product rules**: no number is better than a wrong number; defaults are absolute mm and
  never rescale; cap-and-warn or refuse with a `422` naming the fields, never guess — `L02`.
- **Gate**: `make verify` is the only definition of done; it runs as the pre-commit hook,
  in CI and inside `make worktree.land` — `L03`. mypy strict with `disallow_any_explicit`
  from the first line — `L04`. No automatic formatter — `L05`. `requirements.txt` is the
  pinned closure, used as a pip constraint — `L06`.
- **Module graph, enforced by import-linter**: pure maths never imports the CAD kernel; the
  CAD module is the only doorway to `cadquery`/`OCP`; the CLI never imports the web layer;
  the serving process never imports the kernel. Contracts land with the modules.
- **Measurement before knobs**: every runtime bound (timeout, memory limit, gzip level,
  worker count, any cap) comes from a recorded bench run cited in the decision that set
  it. Nothing is tuned toward a pass.
- **Records**: the decision log is append-only; tech debt and ideas are one file per item
  with an INDEX, a severity and a named trigger; debt is retired in the fixing commit.
- **Language**: English in every document, identifier, comment and commit.
