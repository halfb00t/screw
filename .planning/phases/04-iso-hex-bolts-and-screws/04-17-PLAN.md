## Phase Goal

ROADMAP **Goal** (verbatim; not in user-story form, so no story is invented here): A user picks
"M6 × 20, ISO 4017" (or an ISO 4014 size and length) and gets a hex head bolt or screw whose
explicit millimetre fields were filled from a cited, tested table row, with an info panel whose every
number traces to a field or a row.

Gap G-04-5 (04-UAT.md, test 5, "this part doesn't look clean"; root cause in
`.planning/debug/info-panel-full-precision-value-overflows-cell.md`): each info row is a single-line
flex box whose value cannot shrink (`#dims div` with the default `flex-wrap`, `#dims dd` kept on one
line, the flex-item default `min-width: auto`), so in the 200 to 256 px tracks that
`repeat(auto-fill, minmax(12.5rem, 1fr))` makes at most widths the label is crushed to one word a
line and a full-precision value runs into the next cell (`15.011106998930268 mm` over `Head height`).
Full precision is by design (L02, D-19; plan 04-13), so the fix is the row layout, not the number.
The geometry is the same in both themes (the dark block sets colours only).

## Flagged assumptions and choices (for the verifier and the owner)

- Discretion, measured: the label's basis is `50%`, not the debug session's V8 `7rem`. Both give
  zero overflow at every measured width; `7rem` (112 px) would be a length off the locked spacing
  scale, which extension rule 4 forbids and the 04-UI-REVIEW already scored as a defect for plan
  04-13. The visible difference: in a single track of 343 to 356 px (375 and 1024 px viewports) the
  long values sit under their label, where V8 kept them beside a 2-line label. One rule everywhere:
  a value shares the label's line only when the label keeps half the row.
- The `.75rem` gap also separates a wrapped value from its label (the `gap` shorthand covers both
  axes). Kept as measured; the screenshots read cleanly and no new value is added.
