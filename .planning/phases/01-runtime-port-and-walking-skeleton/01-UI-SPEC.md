# Phase 01 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Provenance of this document.** Written after the UI landed (plan 01-04, commits `8fd0ab0` and `6d23fde`), because the execute-phase `ui.safety-gate` halted at wave 4 with no UI-SPEC. It documents and locks what exists in `src/screw/static/index.html` (51 lines), `app.js` (419 lines) and `style.css` (181 lines) as the baseline for Phases 3 to 6 (left-hand field, ISO rows, a nut kind, printability warnings). It invents no redesign. Every as-built choice is recorded as the decision. Where the as-built page conflicts with an owner decision (D-xx), an L02 rule or the template's own quality rules, the conflict is listed in **Open Issues** at the end and the contract body still describes the code. Line references (`app.js:NN`) are as of `6d23fde`.

No user was asked anything in this run. Every answer comes from `01-CONTEXT.md`, `01-RESEARCH.md`, `01-04-PLAN.md`, `01-04-SUMMARY.md`, the as-built files, the live API documents (printed from the running app this session) and spur's viewer lineage (L07). Anything not resolvable from those is marked `ASSUMPTION:`.

**Hard constraints (from `CLAUDE.md`, `docs/CODING_VALUES.md`, the decision log, 01-CONTEXT):**

- Vanilla JS (one ES module) plus the vendored three.js bundle. No framework, no CSS framework, no build step except `web/` for the bundle (`make vendor-check`).
- Every number shown comes from the API (`/api/<kind>/info` `rows` and `warnings`). The UI never computes a dimension. It never rounds one (target rule, see OI-1 for the as-built deviation).
- A parameter the user did not set never silently changes the part (L02). An omitted `kind` in the hash means `bolt` forever (D-09).
- The skeleton is internal and never released. The info `warnings` carry the exact string `walking skeleton: plain unthreaded cylinder, not a product build` (D-06).
- The `L/P` turn count is not shown (CONTEXT specifics).
- No per-kind label table, no field-name literal and no row-key literal in `app.js` (D-09, D-10).

### Layout

- `body` is a column flex: `header`, then `main` (`flex: 1`).
- `main` is a two-column grid: `minmax(290px, 350px) 1fr`. Left: `aside` (scrolls on overflow, `--panel` surface, right border). Right: `#view`.
- `#view` is a column flex: `#canvas-wrap` (`flex: 1`, `min-height: 320px`, `--view-bg`) over `#bottom`.
- `#bottom` is a two-column grid `minmax(0, 1fr) minmax(0, 1.4fr)`: left column downloads then messages, right column the info panel `#dims`.
- `#dims` is a grid `repeat(auto-fill, minmax(12.5rem, 1fr))`, label left and value right in each row, dashed bottom border per row.
- Breakpoint `max-width: 820px` (one breakpoint, no others): `main` becomes a column, `#view` moves first (`order: -1`), `#canvas-wrap` is `55vh` with `flex: none`, `#bottom` is a single column, the aside gets a top border instead of a right border.

## Interaction Contract

### Form and schema

1. The form is built from `schema.properties` in property order (= model declaration order: `d`, `pitch`, `length`). A `fieldset` and `legend` is created per distinct `group`, in first-seen order.
2. Control choice: `enum` gives a `select`; otherwise `input[type=number]` with `inputMode="decimal"`. There is no boolean branch yet; the checkbox lands with `left_hand` in Phase 3 and must stay schema-driven.
3. Bounds: `input.max` is the schema `maximum` (100000 for `d` and `length`, the INTERIM bound `INTERIM_MAX_MM`, D-14). `input.min` is set only from `minimum`, never from `exclusiveMinimum`, because HTML `min` is inclusive and the server's 422 must speak (Pitfall 5). `input.step` is the schema `step` (0.1, 0.05, 0.5), else 1 for integers, else `any`.
4. Help text: `description` is the label's `title` tooltip and a `small` line shown only while the field has focus (`.field:focus-within small`).
5. Typing does not validate in the browser (the form never submits); the server is the only validator (L02, validated once at the model boundary).

### Hash (the shareable link)

6. Grammar: `#[kind=<kind>&]<name>=<value>&...`, serialised with `URLSearchParams`. `kind` first (only when it differs from `/api/kinds` `default`), then fields in form order. Only fields that differ from their default are written. Numbers compare as numbers (`Number(input.value) !== Number(defaults[name])`), so `6.0` equals the default `6` and is not written; selects compare as strings. An empty field is never written.
7. An empty hash is the default kind with every field at its default. A hash without `kind` means `bolt` forever (D-09, L02).
8. The hash is written with `history.replaceState`: no history entry per edit, no `hashchange` from the page's own writes. When the result is empty the URL is `location.pathname + location.search` with no `#`.
9. Reading: `navigate()` is the single entry for startup, `hashchange` and the kind selector. It reads `kind` (`?? kinds.default`), rebuilds the form only when the kind changed, then sets each input to `h.get(name) ?? defaults[name]` and builds.
10. Foreign or unparseable hash keys are not refused today (OI-2).

### Update loop

11. Typing in any field (`input` event) schedules `update()` after 350 ms, restarting the timer on each keystroke. 350 ms is INTERIM (D-01, carried from spur `app.js:221`, a UI choice never measured for screw; Phase 7 re-sweeps, OPER-02; tracked in `docs/tech_debt/active/2026-10-05-interim-runtime-bounds.md`).
12. `navigate()`, kind change and `Reset` build immediately with no debounce. `navigate()` also cancels the pending debounce and aborts the in-flight request.
13. `update()` sequence: write the hash; clear every `.invalid`; disable both downloads; abort the previous request (`AbortController`); set status `Building…`; fetch `api/<kind>/info?<changed fields>`; on success render the panel and warnings; then fetch `api/<kind>/model.stl?<changed fields>&quality=preview`; on success replace the mesh, enable the downloads with the changed-fields query, clear the status.
14. Staleness: a monotonically increasing `seq` discards any response that is not the newest, and a `formSeq` discards a schema response overtaken by a newer navigation (Pitfall 6). `navigate()` bumps both on every call.
15. Failure (any 4xx or 5xx or network error): the messages area shows only the error paragraphs, the panel is emptied, downloads stay disabled, and the status reads `Showing the last valid part` when a mesh exists, otherwise empty. The last valid mesh stays on screen.
16. The info panel renders before the preview mesh arrives (info is fetched first), so for the length of one STL build the panel can describe a newer part than the mesh shows. `Building…` is on screen during that time.
17. Downloads link to `api/<kind>/model.stl` or `model.step` with only the changed fields and no `quality`, so the server default `fine` applies. The preview always uses `quality=preview`. The browser takes the filename from the server's `Content-Disposition` (`<kind>_<fields>.<fmt>`, built by the server from validated floats).
18. A disabled download is `a.btn[aria-disabled="true"]` with no `href` (opacity .45, `pointer-events: none`). It is not focusable.
19. `Reset` sets every input to its default and runs `update()`. `Copy link` copies `location.href`.

### Kind selector

20. The selector is filled from `/api/kinds` (`new Option(k, k)`). Changing it writes `kind=<k>` (nothing for the default kind) and navigates. A new kind starts from its own defaults; no field carries over (ASSUMPTION, plan 01-04 flagged: carrying `d` and `pitch` across is the matching-part feature TYPE-04 in Phase 5, unobservable with one kind).
21. A hash naming an unregistered kind clears the form, sets `currentKind = null`, deselects the selector, empties the panel, disables the downloads, shows the unknown-kind error and builds nothing. While `currentKind` is null `update()` returns immediately, so no keystroke can build the default part under a link that named another kind (L02).

### Info panel

22. For each `info.rows` entry, in server order, one `div` with a `dt` (`row.label`) and a `dd` (`<fmt(row.value)> <row.unit>`, trimmed). Nothing else of `info` is read except `info.warnings`. No row is looked up by key.
23. Display of the number: `fmt = (v) => Number(v).toFixed(3).replace(/\.?0+$/, '')` (`app.js:18`). This rounds in the browser and is an open defect (OI-1). The target contract is that the page shows the API's number as sent.
24. Warnings are `p.warning` paragraphs under the downloads, in server order, after any error paragraphs. A warning is never hidden, truncated or reworded by the page (but see OI-3).

### Viewport

25. Z-up camera, perspective FOV 35, hemisphere light plus a directional key light attached to the camera, orbit controls, a ground grid sized to the part (step chosen from 0.5, 1, 2, 5, 10, 20, 50, 100, else 200, so at most 24 cells across, placed 0.01 mm below the part), feature edges at a 40 degree threshold. Pixel ratio is capped at 2. Rendering is on demand, coalesced with `requestAnimationFrame`.
26. The view refits automatically on the first model and whenever the part's bounding-box diagonal changes by more than 30 percent; otherwise the user's camera is kept. `Fit` always refits.
27. Theme follows `prefers-color-scheme`, including live changes; the grid, background, mesh and edge colours are read from the CSS tokens.

### Safety rules (pinned by source assertions)

28. Every DOM node is built with `createElement`, `textContent`, `Object.assign` or `new Option`. `innerHTML` and HTML-string assignment never appear in `app.js` (T-01-15).
29. `app.js` contains no per-kind label table and no quoted field name or row key (`d`, `pitch`, `length`, `volume`) and does not read a property of `info` other than `rows` and `warnings`. 01-04's plan and summary name these statements as the ones plan 01-05's parity test pins; the test does not exist yet, so an executor must not reword them: `fetch('api/kinds')`, `for (const [name, prop] of Object.entries(schema.properties)) {`, `fields.set(name, { input, wrap, title });`, `const kind = h.get('kind') ?? kinds.default;`, `for (const row of info.rows) {`, `hashQ.set('kind', currentKind)`, `Number(input.value) !== Number(defaults[name])`.

### Accessibility as built

- `#status` is `role="status"`; `#messages` is `aria-live="polite"`; the canvas has an `aria-label`; every control is a native element inside a wrapping `label`.
- Focus rings are the browser default (`ASSUMPTION:` not verified in a browser). Invalid fields are marked by border colour and outline plus the error text naming the field; no `aria-invalid` is set (OI-5).
