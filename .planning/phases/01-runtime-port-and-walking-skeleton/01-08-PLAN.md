## Phase Goal

ROADMAP **Goal** (verbatim; not in user-story form — run `/gsd-mvp-phase 1` to restate it; not invented here): A user can generate a walking-skeleton bolt (`d`, `pitch`, `length`, plain unthreaded solid; an internal milestone, never released) from the web UI, the HTTP API and the CLI, all served by spur's ported runtime from one registered model, with front-end parity proven by one test over the registry.

<objective>
The bench harness (L07: "as a harness, not as numbers"): build time, export cost, latency under
load and the container memory sweep, ported with their method and run once against the skeleton.

Purpose: success criterion 3's "the bench/ harness runs against the skeleton"; Phase 2 and Phase 7
re-use it on threaded parts.
Output: bench/ package, README, RESULTS.md with one labelled run of each half, tests/test_bench.py.
</objective>
