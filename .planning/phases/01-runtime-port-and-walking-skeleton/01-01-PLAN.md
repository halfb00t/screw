## Phase Goal

ROADMAP **Goal** (verbatim; it is not in "As a / I want to / so that" form — run `/gsd-mvp-phase 1` to restate it; no story is invented here): A user can generate a walking-skeleton bolt (`d`, `pitch`, `length`, plain unthreaded solid; an internal milestone, never released) from the web UI, the HTTP API and the CLI, all served by spur's ported runtime from one registered model, with front-end parity proven by one test over the registry.

<objective>
The walking-skeleton tracer: one real request path through every layer the phase ports — the
registered `bolt` model (`params`), its kernel-free info document (`calc`), the kernel doorway
(`solid`), the worker pool (`pool`), the log vocabulary (`records`) and the HTTP API (`app`) —
proven end to end by `docker/smoke.py` driving the ASGI app through its lifespan. Then the
owner vets three flagged dev packages, and the pool's ported tests land with the one deliberate
divergence from spur (the D-16 same-slot guard) and its regression test.

Purpose: catch an architectural dead end (registry + per-kind Query models + kernel isolation)
on the first commit, not after the CLI, UI, wall and image are layered on top.
Output: 9 source files, the smoke driver, contracts 2/4/5/8, 5 test files, the approved dev extras.
</objective>
