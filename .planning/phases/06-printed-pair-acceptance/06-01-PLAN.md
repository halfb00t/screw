## Phase Goal

ROADMAP **Goal** (verbatim; not in user-story form, so MVP mode frames no story here; run
`/gsd-mvp-phase 6` if the owner wants it restated): The owner holds a bolt and a nut printed from this
tool at the default clearance that thread together by hand, and that default and the printability
threshold come from a recorded printed test, not from a forum or vendor figure.

<objective>
The code half of the pre-registration (SC1): the rules that will read the owner's record, and the matrix
that says what to print, written and tested before any record exists. Task 1 is the tracer: a synthetic
record through the strict reader and the D-07/D-08, D-14 and D-10 rules. Task 2 adds the matrix as data,
the export lists, the manifest writer and the three blank records.

Purpose: every number this phase ships is a reading of a record (RESEARCH "Key insight"), so the reading
must be mechanical and fixed before the data. Output: two kernel-free bench modules, three blank records,
their tests, the import contract, all on the pre-registration branch. Plan 06-03 adds the protocol and
opens PR A; plan 06-04 lands it.

Where work happens: in a separate worktree on a branch cut from `origin/main` (Phase 5 05-01 pattern).
The main checkout stays on `gsd/phase-06-printed-pair-acceptance` the whole time; switching it would
delete this plan from under the executor. `make worktree.new` branches off HEAD (the phase branch, which
carries planning commits `origin/main` lacks), so step 1 calls `git worktree add` directly. A
`.claude/worktrees/phase-05-preregistration` worktree already exists; leave it alone.

Where checks run: tests and `make verify` run inside the worktree in the actions, and the pre-commit
hook re-runs `make verify` there on every commit. Every `<automated>` check runs from the main checkout
root and reads the branch through git.
</objective>
