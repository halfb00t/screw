## Phase Goal

ROADMAP Phase 8 goal (verbatim, not a user story): Close the gaps the v1.0 milestone audit found so the
first release ships with OPER-03 met: no admitted part ends in a kernel `422 build_error`, every build
path has a deadline or a logged reason it has none, and the front ends answer the same part the same
way.

This plan closes SC4 (INT-03): a value typed equal to its default gets the same answer on the web, the
API and the CLI.

<objective>
Make the web count a typed, picked or linked field as explicit, as the API and the CLI do; prove the
same answer on the three front ends; log it as L35 and amend L19, L21 and the UI-SPEC in the same
change.

Purpose: today a typed `thread_length=20` is silently capped on the web and refused on the API and
the CLI (audit INT-03), which breaks L02's "a parameter the user set" rule. Output: the `touched` set
in app.js, the parity tests, L35, the amended L19 and L21 notes and UI-SPEC rules.
</objective>
