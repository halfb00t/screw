## Phase Goal

ROADMAP Phase 8 goal (verbatim, not a user story): Close the gaps the v1.0 milestone audit found so the
first release ships with OPER-03 met: no admitted part ends in a kernel `422 build_error`, every build
path has a deadline or a logged reason it has none, and the front ends answer the same part the same
way.

This plan was 08-08's second half, split off so each plan fits the context budget. 08-08 shipped the
fine-sweep feature (`FINE_COEFFICIENTS`) and `FINE_ENVELOPE` as constants and recorded L38's
shipped-side widening; this plan writes that widening into fit.json and `ENVELOPE` (F16 (i)), then makes
admission read the fine pair, each in the one commit that `make verify` requires, and records F10 and
F16 in RESULTS. It runs after 08-08 (wave 8) and before 08-09. Replanned 2026-11-04 for the owner's S9
ruling (L38, F16); the scratch figures below are the planner's recompute at replanning, not evidence.

<objective>
Widen `ENVELOPE` for the two nut `step` models L38 names, switch `cost.fits` to the fine-sweep feature
and `FINE_ENVELOPE` for fine-swept parts, show that nothing drawn before Phase 8 and no runtime value
beyond R21's count moved, and record it all in RESULTS.

Purpose: the host check showed the shipped model underpredicts some shipped-sweep nuts at `step`, and
the fine sweep costs more time and STEP bytes than the shipped fit predicts; admission must cover both
or a part could pass its timeout or budget (D-05, L38), while every part at or below a threshold keeps
its admission but for what L38's widening refuses (D-02). Output: fit.json and the block with L38's two
values, the F12 rule for the tier files, the sweep-aware `fits`, the re-derived `runtime.json`, the
re-pins and a RESULTS section.
</objective>
