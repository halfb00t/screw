## Phase Goal

ROADMAP **Goal** (verbatim; not in user-story form, so the MVP user-story framing is not invented
here): Every configuration a user is allowed to ask for builds inside a per-build timeout measured on
linux/amd64 over the full grid, or is capped and warned or refused with a `422`, and every runtime
bound cites the run that set it.

Spec-less probe fallback applied: the OPER-03 empty edge for the cap path (an admitted part is never
capped) is the fifth truth.

<objective>
Implement D-06's second half as the owner ruled it in B-03: a defaulted value that pushes a part over
its budget is capped and warned, on the API and the CLI alike, and an explicit one stays a 422. Then log
the whole cost-model decision as L21.

Purpose: the goal's "capped and warned or refused with a 422" for every configuration. Output:
`cost.cap_defaults`, its wiring on both front ends, L21.
</objective>
