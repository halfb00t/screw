## Phase Goal

ROADMAP **Goal** (verbatim; not in user-story form, so the MVP user-story framing is not invented
here): Every configuration a user is allowed to ask for builds inside a per-build timeout measured on
linux/amd64 over the full grid, or is capped and warned or refused with a `422`, and every runtime
bound cites the run that set it.

Spec-less probe fallback applied: the OPER-01 adjacency (a queued request keeps its own full timeout)
and empty (nothing ahead) edges are the second and third truths.

<objective>
Make the timeout mean what D-09 needs before anything is measured against it: the per-build clock
stops counting time spent queued behind another build on the same slot (D-14), the timeout becomes a
per-artifact table with no environment override (D-09, D-16), and an admitted part that still times
out is logged as a cost-model miss (D-10).

Purpose: the pool code and its tests are ready for plan 07-16 to drop the measured seconds in.
Output: a queue-aware `BuildPool`, `screw.calc.cost` with the artifact names, `records.cost_model_miss`.

Where work happens: the main checkout on `gsd/phase-07-operability-re-sweep`. It runs in parallel with
07-01, which works in a separate worktree; this plan touches no `Makefile`, `pyproject.toml`,
`bench/` or workflow file, so merging `origin/main` back in plan 07-04 meets no conflict.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-04 | Denial of service | `_run_with_timeout` deadline | medium | mitigate | the deadline grows only with requests already admitted on the slot, which `MAX_QUEUED_BUILDS` bounds; each running build still dies at its own timeout because deadlines on a slot are strictly increasing |

| T-07-SC | Tampering | package installs | low | accept | no package is installed or added |
