## Decisions this plan makes, and why

Each was delegated to the planner. None needs a checkpoint, because the code and the rulings settle it.

- **WR-01: build every accepted s; add no refusal.** The geometry confirms the threshold. `face_chamfer` starts its profile at `(s/2 - 0.5 / tan 30 deg, z_face -/+ 0.5)`, and that radius is negative for s < 2 * 0.5 / tan 30 deg = sqrt(3) = 1.7320508 mm. The planner's scratch probe ran at HEAD ad09d46 with d 1, pitch 0.25, m 1 and clearance 0.05. s 1.5, 1.7 and 1.732 failed with `Standard_Failure`. s 1.7321, 1.74 and 2.0 built. With the overshoot capped at (s/2) tan 30 deg / 2, every case built inside T_GATE: s 1.5, 1.7, 1.732, s 1.11, left hand, m 0.05, and d 0.5 at s 0.6. The defect is in the cutter, not in the input. No rule gives a minimum s to mirror: the bolt's only s rule is s > d (`head_too_small`), the nut's is s > d + 2c (D-13), and the smallest GOST ISO 4032-2014 row is M2 with s 4. A floor would refuse a valid part for a construction detail. The overshoot lies outside the nut, so it cuts the same solid, and the oracle never sees it. For s of 2 sqrt(3) mm (3.464) or more, the profile is the old one.
- **WR-02: guard at two boundaries; leave the rule's clauses alone.**
  - *The rule.* Both tolerance comparisons become negated `<=` (`volume_check`'s pattern). The code then tests what the written rule says ("within `T_PASS`", "within `PAIR_BAND`").
  - *Planted matched NaN.* It stays `violated`, because 02-SPIKE Rules defines empty as 0 solids or |volume| <= 1e-6, so a NaN reading is non-empty. Reclassifying it would amend the pre-registered rule, which needs an owner ruling (the 2026-10-10 WR-04 precedent).
  - *The harness.* `prove` refuses a non-finite kernel volume where it reads one, as a failure. This mirrors the spike's record parser `_num`, which refuses a non-finite number "because a NaN volume would compare as not outside the tolerance". So the product never hands the rule a NaN.
- **WR-03: make the behaviour match the docstring, not the other way round.** A closed form printed beside `band` tells the reader the controls were judged against it. Printing one on a failure, a violation or a nut body nobody believes claims a comparison that never ran (L02). So the rule returns what it used (`cell_judgement`), and `prove` does not copy the rule's gate sequence.
- **WR-04: an honest "inconclusive by definition"; no larger blank.** D-05 locks the blank at radius d, and the expected table stands on it. R8 sets the shape for c <= 0: nothing is read and the verdict is inconclusive by definition. The larger blank would not change the verdict:
  - For every nut the CLI accepts (rod root d/2 - 5H/8 above 0), c >= d/2 exceeds the thread depth 5H/8.
  - So the void's root radius clears the rod's crest at every phase, and the control's closed form is 0.
  - The rule's own clause, "a control whose closed form is at or below EMPTY_MM3 cannot fire by geometry", then reads `inconclusive` whatever the blank.
  The short-circuit gives that same verdict without a closed form that is invalid outside c < d/2. At the review's input (d 6, pitch 1, clearance 3.5) that closed form reads -39.6362 mm3.
- **WR-06: give the evidence bolt the nut's own s off a row.** D-03 leaves an off-row counterpart at the bolt's frozen s of 10, which `head_too_small` refuses for d >= 10. The nut's s is a value the user set, and it lies above d + 2c, so above d at every c > 0 where the row is taken. ISO 4017:2022 and GOST ISO 4032-2014 print the same s at all 14 sizes they share (planner check of `tables/iso4017.HEADS` against `tables/iso4032.NUTS`), and k stays the bolt's frozen default. The head never enters a reading: the nut starts 2P up, so its top at the highest pose is m + 7P/3, and the bolt is tip + m + 2P long with tip = 0.5413 P. On a row nothing changes.
- **No `make pair` re-run.** No grid cell has a non-finite reading or a clearance of d / 2 or more. `closed_control` is not a verdict input. The grid ran `shipped=False`, so it has no evidence row. The table is re-derived instead and must come out byte-identical; any difference stops the plan.
- **Found while planning, filed rather than fixed.** The planner's scratch probe at ad09d46 found a second cutter defect. `countersink_inner_radius` returns `root - 0.3 * thread_depth`, which is negative when the void's root radius is below 0.3 thread depths. At d 2, pitch 1.5, clearance 0.05, s 4, m 3 it gives -0.0055 mm, and at pitch 1.8 it gives -0.2166 mm. Both nuts are accepted by the model and refused by the kernel with `Standard_Failure`. Capping it at max(root - 0.3 td, root / 2) built both inside T_GATE with passing preview STLs. At clearance 0.01 (void root 0.036 mm) the build still refused, with "invalid solid", which is the root-floor class. The owner fixed this plan's scope, so Task 4 files it as debt and does not fix it.
