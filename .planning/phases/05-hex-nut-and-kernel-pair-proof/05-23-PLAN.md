## Phase Goal

ROADMAP **Goal** (verbatim; it is not in user-story form, so no story is invented): For any bolt a user can get the matching ISO 4032 nut at a chosen radial clearance, see the pair's numbers on the info panel, and get a kernel verdict on whether the pair mates, one that cannot report `proven` when its own control did not fire.

This plan closes the two gaps of 05-VERIFICATION.md (re-verification 2026-10-21, `gaps_found`, 19/20). Both are in plan 05-22's page memory of the typed clearance.

- **WR-07 (failed must-have, 05-22 truth 3).** `rememberTyped` keys the memory by `currentKind`. A kind switch sets `currentKind` only after `await loadPresets()`, while `buildForm()` has already put the new form on screen. A clearance typed in that window is stored under the bolt. The nut's `Matching bolt` link then reads `#kind=bolt&clearance=0.1&...`, and `navigate()` refuses it for the rest of the page session.
- **WR-08 (partial).** Reset and a link change the field without touching the memory, so the bolt's `Matching nut` link carries a number the nut no longer shows.

Owner's decisions this session (2026-10-21, verbatim from the orchestrator):
- WR-08: **forget on Reset and on a link**. Reset forgets the remembered entry for a field it empties. A navigate, link or Back that writes a different value into a field with no default drops the remembered entry (05-REVIEW.md WR-08 `forgetUntyped`). The wording "never an empty or stale number" in UI-SPEC rule 37, the app.js comment and the L15 amendment then stays true. Rule 37 and the L15 amendment text are updated to describe the built behaviour, dated and naming WR-08, in the same commit as the code.
- WR-07: fix it as 05-REVIEW.md WR-07 gives. Key the memory by a `formKind` that buildForm sets in the same synchronous block as `defaults`, that clearForm clears, and that rememberTyped and forgetUntyped use. Add the IN-05 source pin (`lastTyped.set(` keyed by `formKind`, not `currentKind`) and the IN-06 guard in `rowOfFields` for a control the form lacks.

## Decisions this plan makes, and why

- **`forgetUntyped(input)` takes the control, not `(name, written)`.** The review's sketch compared `String(written ?? '')`. This plan reads the control after the write (`read(input)`), the same reading `rememberTyped` stores. So "a different value" is judged on the string the field now shows, with no conversion: a link `clearance=0.10` against a typed `0.1` forgets, because the field shows `0.10`. The name and the owner's rule are the review's.
- **One forget line per call site, after the write loop.** In `navigate()` the existing write loop is a pinned statement (`PINNED_STATEMENTS`, rule 29), so it stays byte for byte. A second line, `for (const { input } of fields.values()) forgetUntyped(input);`, follows it directly. The Reset handler gets the same line. `forgetUntyped` deletes only a key the memory holds, and only fields with no default ever enter the memory, so calling it for every control needs no default check.
- **The forget comes before navigate's unreadable-value refusal.** A link that wrote `abc` into the field has changed it, and a refusal does not undo the write. A link refused before the write (repeated key, unknown kind or field) never wrote the field, so it forgets nothing.
- **A kind switch by the selector is a navigation.** Switching to the nut writes its empty clearance and forgets a clearance typed earlier. Switching to the bolt writes only bolt fields and leaves the nut's memory alone. That is how the round trip `Matching bolt` then `Matching nut` keeps 0.1 (the nut's write puts back the same 0.1). The probe pins both.
- **`currentKind` keeps its role.** It still drives `update()`, `setDownloads` and the hash. Only its trailing comment is corrected: it described the form, which is how WR-07 happened. The comment now says it is the kind the last finished navigation loaded.
- **Commits.** There are three, one concern each: WR-07 with IN-05 and IN-06 (a bug fix that makes the documented invariant true again, so no contract text changes), the debt item, then WR-08 with its decision-log amendment and the UI contract, which the owner asked to be in the code's commit.

import json
import os
import sys
from pathlib import Path

from playwright.sync_api import sync_playwright

BASE = sys.argv[1]  # e.g. http://127.0.0.1:8023/
OVERRIDE = os.environ.get("SCREW_PROBE_APP_JS")  # planner grounding only; unset in the plan run
LINK = ("() => document.querySelector('#counterpart').hidden ? null"
        " : document.querySelector('#counterpart').getAttribute('href')")
ERRORS = "() => [...document.querySelectorAll('#messages p.error')].map(p => p.textContent)"
SELECTS = "() => [...document.querySelectorAll('#picker select')].map(s => s.value)"
NUT_M6 = "#kind=nut&d=6&pitch=1&left_hand=false&s=10&m=5.2"
BOLT_M6 = "#kind=bolt&d=6&pitch=1&left_hand=false&s=10&k=4"
failed = []


def check(step, ok, detail):
    print(("PASS " if ok else "FAIL ") + step, json.dumps(detail))
    if not ok:
        failed.append(step)


def new_page(browser, seen, pageerrors):
    page = browser.new_page()
    if OVERRIDE:
        body = Path(OVERRIDE).read_text()
        page.route("**/static/app.js", lambda r: r.fulfill(content_type="text/javascript", body=body))
    page.on("response", lambda r: seen.append((r.status, r.url.split("/api/", 1)[1])) if "/api/" in r.url else None)
    page.on("pageerror", lambda e: pageerrors.append(str(e)))
    return page


def built(page, kind):
    return page.expect_response(lambda r: f"/api/{kind}/model.stl" in r.url and r.status == 200, timeout=60000)


def stls(seen, kind):
    return [s for s, u in seen if u.startswith(f"{kind}/model.stl")]


with sync_playwright() as pw:
    browser = pw.chromium.launch()

    # WR-07 and IN-06: a clearance typed while the nut's catalogue is still loading.
    seen, perr, held = [], [], []
    hold = {"on": False}
    page = new_page(browser, seen, perr)
    page.route(lambda url: "/api/presets?kind=nut" in url,
               lambda r: held.append(r) if hold["on"] else r.continue_())
    with built(page, "bolt"):
        page.goto(BASE)
    hold["on"] = True
    seen.clear()
    page.select_option("#kind", "nut")
    page.wait_for_selector("input[name=clearance]")
    page.wait_for_timeout(300)
    # The new form is on screen with every control still empty: typing d and pitch lets
    # rowOfFields reach a bolt row's field the nut form lacks (IN-06).
    page.fill("input[name=d]", "6")
    page.fill("input[name=pitch]", "1")
    page.fill("input[name=clearance]", "0.1")
    page.wait_for_timeout(900)  # the 350 ms debounce fires inside the window
    window = {"requests": [u for _, u in seen], "hash": page.evaluate("location.hash"), "held": len(held)}
    print("OBS window", json.dumps(window))
    hold["on"] = False
    for r in held:
        r.continue_()
    page.wait_for_timeout(2500)
    check("window: no page error while the kind switch loads (IN-06)", perr == [], perr)
    check("premise: the finished navigation writes the link's empty clearance over the window's typing",
          page.input_value("input[name=clearance]") == "" and page.evaluate(SELECTS) == ["ISO 4032", "M6"],
          {"clearance": page.input_value("input[name=clearance]"), "selects": page.evaluate(SELECTS)})

    href = page.evaluate(LINK) or ""

    page.close()

    # WR-08 case 2: a link writes a different clearance, so the memory forgets the typed one.

    page.goto(BASE + "#kind=nut")
    page.wait_for_selector("#picker select")
    with built(page, "nut"):
        page.fill("input[name=clearance]", "0.1")

        page.evaluate("location.hash = '#kind=nut&clearance=0.3'")
    check("premise: the link wrote 0.3 into the field", page.input_value("input[name=clearance]") == "0.3",

    # UAT test 1 (05-21): with an empty clearance a pick holds.

    page = new_page(browser, seen, perr)

        page.goto(BASE)
