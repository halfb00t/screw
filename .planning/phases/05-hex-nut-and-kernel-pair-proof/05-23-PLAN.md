## Decisions this plan makes, and why

- **`forgetUntyped(input)` takes the control, not `(name, written)`.** The review's sketch compared `String(written ?? '')`. This plan reads the control after the write (`read(input)`), the same reading `rememberTyped` stores. So "a different value" is judged on the string the field now shows, with no conversion: a link `clearance=0.10` against a typed `0.1` forgets, because the field shows `0.10`. The name and the owner's rule are the review's.
- **One forget line per call site, after the write loop.** In `navigate()` the existing write loop is a pinned statement (`PINNED_STATEMENTS`, rule 29), so it stays byte for byte. A second line, `for (const { input } of fields.values()) forgetUntyped(input);`, follows it directly. The Reset handler gets the same line. `forgetUntyped` deletes only a key the memory holds, and only fields with no default ever enter the memory, so calling it for every control needs no default check.
- **The forget comes before navigate's unreadable-value refusal.** A link that wrote `abc` into the field has changed it, and a refusal does not undo the write. A link refused before the write (repeated key, unknown kind or field) never wrote the field, so it forgets nothing.
- **A kind switch by the selector is a navigation.** Switching to the nut writes its empty clearance and forgets a clearance typed earlier. Switching to the bolt writes only bolt fields and leaves the nut's memory alone. That is how the round trip `Matching bolt` then `Matching nut` keeps 0.1 (the nut's write puts back the same 0.1). The probe pins both.
- **`currentKind` keeps its role.** It still drives `update()`, `setDownloads` and the hash. Its trailing comment is corrected: it described the form, which is how WR-07 happened. The comment now says it is the kind the last finished navigation loaded.
- **The update guard is a condition on update's existing first line** (owner choice (a)). `if (currentKind === null) return;` becomes `if (currentKind === null || formKind !== currentKind) return;`. Because it is the first statement, nothing in `update()` runs in the window: no hash write, no `.invalid` clearing, no request, no `fail()`. That is also why the probe's IN-06 step now passes on the update guard alone. With no update running in the window, the probe cannot reach `rowOfFields` there, so the IN-06 guard in `rowOfFields` is pinned by the source test only, and stays as the owner asked.
- **Navigate rebuilds when the form on screen is not the link's kind** (owner choice "fix in navigate").
  - The condition becomes `if (kind !== currentKind || kind !== formKind) {`. The rest of the block (`dropMesh()`, `buildForm`, `loadPresets`, `currentKind = kind`) is unchanged.
  - The old condition is pinned verbatim in `test_a_kind_change_drops_the_old_mesh_and_what_described_it`, so that one assertion becomes the source pin, with a comment for the Back case.
  - Trade-offs, checked by the planner. The extra clause is true only when an overtaken navigation replaced the form and the newer one names the old kind. Then:
    - the mesh was already dropped by the overtaken navigation;
    - the picker is still the old kind's, because the overtaken catalogue fetch never built one;
    - the cost is one schema and one presets request (measured: `schema?kind=bolt`, `presets?kind=bolt`).
  - In every other path the clause is false or `kind !== currentKind` is already true: a normal switch, a same-kind link, after a refusal (both null), or a schema fetch overtaken before `clearForm()` (the form and `formKind` are still the old kind's). No new trade-off was found.
- **Commits.** There are two, one concern each:
  - WR-07, meaning the memory key, the update guard and navigate's rebuild condition, with IN-05 and IN-06. It is a bug fix that makes the documented invariant true again, so no contract text changes.
  - WR-08 with its decision-log amendment and the UI contract, which the owner asked to be in the code's commit. The UI contract also gains the rule 14 sentence for the guard and the rule 36 sentence for the rebuild.
