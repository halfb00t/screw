## Phase Goal

ROADMAP **Goal** (verbatim; it is not in user-story form, so no story is invented): For any bolt a user can get the matching ISO 4032 nut at a chosen radial clearance, see the pair's numbers on the info panel, and get a kernel verdict on whether the pair mates, one that cannot report `proven` when its own control did not fire.

This plan closes review finding **WR-10** (05-REVIEW.md, re-review after 05-24), in full as the reviewer filed it and as the owner scoped it on 2026-10-22. 05-VERIFICATION.md (`human_needed`, 37/37) carries WR-10 as a recorded warning, not a must-have gap, so the gap source is the review finding.

- **The failure path.** `navigate()` runs `clearForm()` and `clearPicker()`, then `await buildForm(kind)` unwrapped. When `api/schema?kind=<new>` fails, the page keeps no controls, a Kind select reading the new kind (which a select does not report as a change when picked again), and the old part's info panel, `Matching <kind>` link and two live download links. Before 05-24 the old form at least stayed usable.
- **The stale panel during a switch (owner decision: include it).** From the start of a kind switch until the new kind's first info document, the old part's panel, link and downloads stay on screen. That part predates 05-24.

- **The recovery (orchestrator item 1).** A failed schema or catalogue fetch on any navigation, startup included, goes to `refuseLink`, the page's one "cannot honour this" exit (rule 10).
  - What the page shows: `Could not load the part: <message>` (for a 500, `Could not load the part: 500 Internal Server Error`; for a network error the browser's text, `Failed to fetch` in Chrome), and nothing else. No controls, picker, badge, panel, `Matching <kind>` link, downloads, mesh or status.
  - What the Kind select reads: nothing. `refuseLink` sets `kindSelect.selectedIndex = -1`, as after an unknown kind (rule 21, E2 error). It does not read the kind that failed, because no part of that kind is on screen.
  - How the user retries: pick any kind in the selector, the one that failed included (a deselected select reports any pick as a change). After the matching-part link, Back reopens the part before it. A reload retries the kind the hash names.
  - The hash is not rewritten (rule 10), so a shared link that failed still names what it asked for.
  - Against L02 and the UI-SPEC: no number, link or download is on screen beside a form it does not describe. The page uses an existing exit, an existing message (`Could not load the part: ...`, the catalogue row of the Copywriting Contract) and the existing deselected-selector state. No new control or string.
- **One `try` around both fetches, not the review's separate one.** One error exit serves the schema and the catalogue. The overtaken guard then covers both, and the measured, pre-existing catalogue case closes with the same line. It is also the smaller diff: the `buildForm` line moves into the existing `try`.
- **The overtaken guard.** `navigate()` keeps the `formSeq` it set (`const mine = ++formSeq;`, the name `buildForm`, `loadPresets` and `update` use for the same idea). Its catch returns while `mine !== formSeq`.
  - Measured, without it: the review's patch wipes the bolt the user had switched back to when the nut's schema fails late (A and B), and BASE wipes it when the nut's catalogue fails late.
  - A late success is already dropped (`buildForm` and `loadPresets` return false), so a late failure is now dropped the same way.
- **`setStatus('')` with the clears.** The status is the label of the mesh `dropMesh()` removes. Measured: a failed bolt's `Showing the last valid part` stayed over the empty canvas for the whole schema fetch. UI-SPEC E17 already says the status is empty until a valid nut builds, so this makes the code match the contract. It is one line and reversible, flagged below.
- **The startup consequence is accepted.** The first navigation is a kind switch from none, so a failed first schema fetch now reads `Could not load the part: ...` with the selector deselected, not `Could not load the part kinds and schema: ...` under a selector on `bolt`. Picking bolt then retries, which BASE could not offer. The startup string stays in the code, pinned by `test_the_ui_keeps_the_warnings_of_the_mesh_on_screen`, and is now reached only by a failed `/api/kinds`. The Copywriting rows say so.
- **No retry button.** The deselected selector is the retry, as for every refused link. A retry affordance for 503s is OI-6 (nice, Phase 7); this plan adds no control.
- **`reportLoadError` and the two handlers' `.catch` stay.** After this plan no fetch failure reaches them. An unexpected error that escapes `navigate` still shows a message rather than an unhandled rejection. Removing them is not this finding.
- **The pins (orchestrator item 3, IN-08).**
  - The 05-24 test keeps its name, which UI-SPEC rule 36 and the 05-24 Verification status bullet cite. Its body becomes one ordering assertion: all seven clears come before the first `await` of the kind-change block. A new test pins the one `try`, the guard before the refusal, and `const mine = ++formSeq;`.
  - Both read `navigate` through `_rebuild_block()`, which drops comment lines and squashes whitespace. They count nothing file-wide and no longer re-assert the bodies of `clearForm` and `clearPicker`. That is IN-08's own Fix, option 1.
  - What still pins those statements elsewhere: `formKind = null;` in `clearForm` by `test_the_typed_memory_is_keyed_by_the_kind_of_the_form_on_screen`, and `refuseLink`'s clears by `test_the_ui_refuses_a_link_it_cannot_honour`. The `clearPicker` body is now pinned only by behaviour (the probes). The reviewer called its old pin weak: a shadowing local passed it.
- **IN-08 is recorded `fixed`, on evidence.** The mutant check shows the fragility the reviewer named is gone:
  - the new pins pass another `clearForm()` caller, a split `const built = await buildForm(kind)`, and a comment between the clears;
  - the old pin failed all three against BASE;
  - the new pins still fail on the defects (no guard, the panel cleared after the schema fetch, BASE).
  - The "source text, not behaviour" half stays with the owner's browser-test idea, as IN-05 was recorded (`fixed`, pins tightened). Flagged below: if the owner wants IN-08 open until a browser test lands, it is a one-row revert in commit 2.
- **The edits are grounded patches.** The executor applies two `git apply` patches (test, then app) and one UI-SPEC script, each checked by md5, so no wording is left to interpretation. The comments in the app patch carry the measurements, as CODING_VALUES asks.
- **Commits.** One code commit: app.js, the pins and the UI contract form one concern, "a kind switch leaves nothing of the old part on screen, while it loads or after it fails" (05-24's shape). The disposition is a second, docs-only commit, because it names the first one's sha.
- **Reversibility.** Page state only. Falling back to the review's patch is a revert of the guard, the three panel clears, `setStatus('')` and the moved `buildForm` line. The measured cost of that is above.
