### Locked Decisions

- **D-01:** `head_chamfer` accepts `0 <= beta < 90` degrees, validated once at the model boundary (`ge=0`, `lt=90`, finite). 90 and above is a 422 on the field. 0 builds the sharp head exactly as today, with no cut and no chamfer volume term.
- **D-02:** An angle in the accepted range but outside the ISO 15 to 30 degree band (any value in `(0, 15)` or `(30, 90)`) builds as asked and adds a warning to the info document naming `head_chamfer` and the standard's 15 to 30 degree band. 0 is not off-band. It is the sharp head and carries no band warning.
- **D-03:** The model's corner depth is `(R - s/2) * tan(beta)` with `R = s / 2 / cos 30°`. The allowed depth is `k / 2`, which mirrors the nut's `m / 2` cap (L15). Above the cut, the lower half of the head keeps its sharp corners and the bearing face is untouched.
- **D-04:** When the model depth exceeds `k / 2`:
  - **`head_chamfer` explicit** (in the raw API query or the CLI argv, checked after `--preset` expansion): a 422 naming `head_chamfer` and `k` (CLI: exit 2, same words, parity-tested like `thread_length`). The 422 fires at the same threshold as the cap: `depth > k / 2`. No zone exists where an explicit beta builds a part that differs from its model.
  - **`head_chamfer` defaulted** (30): cap the cut at `k / 2` (a cone plus a flat at that depth, the shape `face_chamfer_volume` already integrates with its `depth` argument) and warn, naming `head_chamfer` and `k`, in the style of the nut's `end_depths` warning.

## Summary

Everything the phase needs already exists in the repo in a form that can be copied: the nut's cone cutter (`nut.face_chamfer`, `src/screw/solid/nut.py:96-115`), its cap-and-warn rule (`end_depths`, `src/screw/calc/thread.py:772-821`), its piece gate (`_build_nut`, `src/screw/solid/__init__.py:162-191`) and the request-boundary conflict hook (`explicit_conflict`, `src/screw/calc/__init__.py:510-544`). The new work is one analytic function, one field, one cutter, one gate, one rule, four info rows, three warnings, one decision entry, and a large but mechanical test update because the **default part changes**.

The analytic closed form (D-07) exists, is elementary, and was verified this session: after one numerical fix it agrees with an independent Gauss-Legendre reference to a worst relative error of 3.4e-14 over 600 rows, and with the shipped numeric `face_chamfer_volume` and the independent `_polar_chamfer` oracle to 4.3e-10 (their own quadrature error) over 108 rows. The uncapped case is one constant: `V = tan(beta) * a^3 * (4/3 + pi/3 + ln 3 - 2 sqrt 3)` with `a = s/2`.

The most important finding for the plan is about **where the cut runs**. Cutting the head prism **before** it is fused to the thread body makes the piece gate accurate to 7e-5 at beta 0.01 degrees and 1.4e-6 or better from 0.5 degrees up, costs about 0.03 s, and refused 0 of 100 head sizes. Cutting the assembled bolt **after** the fuse gives a constant absolute volume bias of about +5.5e-5 mm3 and false-refuses valid parts below roughly beta 0.1 degrees (M6) to 0.5 degrees (M2) at `T_PIECE` = 0.03, at 0.16 to 0.46 s. Recommend the head-only placement, which still satisfies D-09 (own piece gate, before `T_GATE`).

**Primary recommendation:** Add `head_chamfer` (last field of `BoltParams`, `ge=0`, `lt=90`, default 30.0), implement `head_chamfer_volume` in `calc/thread.py` with the stable formulation recorded below, cut the head prism in `_build_bolt` before `bolt.assemble` fuses it, gate that cut at `T_PIECE` against the analytic oracle, and keep `bolt.assemble(p, thread)` building a sharp head by default so `bench/` is untouched.

### Pattern 1: Cut the head before the fuse, gate the piece on the head alone

**What:** Build the sharp prism (`bolt.head`), cut the cone cutter from it, `check_structure`, take precise volumes of the prism before and after, and `piece_refusal(before - after, head_chamfer_volume(...), "head chamfer")`. Then fuse the chamfered head.
**When to use:** always when `p.head_chamfer > 0` and the cut depth is above 0.
**Why:** measured below (Pitfall 1). The piece error is limited by the head's own volume noise, not the whole bolt's.

```python
# Source: scratch kernel_piece.py / kernel_full.py (this session), shaped like solid/nut.py:96-115
PAST_FACE = 1.0   # nut.py:36; the cutter reaches past the top face

def head_cutter(s, z_top, beta, depth):            # all lengths in mm, beta in degrees
    tau = math.tan(math.radians(beta)); r0 = s / 2
    outer = r0 / math.cos(math.pi / 6) + PAST_FACE
    overshoot = min(0.5, r0 * tau / 2)             # keeps r0 - overshoot/tau >= r0/2 (nut.py:111)
    above, flat = z_top + overshoot, z_top - depth
    pts = [(r0 - overshoot / tau, above), (outer, above), (outer, flat), (r0 + depth / tau, flat)]
    return revolve(pts)                            # nut._revolved: XZ polyline, revolve 360 about Y
```

The cutter is the nut's `face_chamfer` mirrored (the nut's top face has `sign = -1`). `head.cut(cutter)` returns a **Compound**, not a Solid (bolt._solid raised `Geometry kernel produced Compound for the head` in scratch): keep it as a `cq.Shape`, check it with `check_structure`, and fuse it as is. `[VERIFIED: scratch run]`

### Pattern 2: One shared depth predicate

The explicit-value rule (D-04), the builder, the oracle, `derive` and the info rows must call one function so they cannot disagree at the boundary:

```python
# Recommended shape (names are discretion)
def head_chamfer_depths(s: float, k: float, angle_deg: float) -> tuple[float, float]:
    """(model depth, cut depth): (corner - s/2) * tan(angle), and min(that, k/2)."""
    corner = s / 2 / math.cos(math.pi / 6)           # the SAME expression end_depths uses (thread.py:814)
    full = (corner - s / 2) * math.tan(math.radians(angle_deg))
    return full, min(full, k / 2)
```

`capped` is `full > k / 2` everywhere (rule, builder, warning). Use `>` not `>=`: equality builds uncapped (D-04 "depth > k / 2").

### Anti-Patterns to Avoid

- **Cut after the fuse:** a constant +5.5e-5 mm3 bias makes `T_PIECE` refuse valid small chamfers (measured below).
- **Forming `rho_c - a` from `a + depth/tan`:** loses `1e-16 * a / x` relative accuracy; use `x = depth / tan` directly.
- **Letting `bolt.assemble` read `p.head_chamfer` implicitly:** `bench/end_cuts.py:309,322,388` and `bench/head_fuse.py:97` call `bolt.assemble(p, thread)` on default `BoltParams` and compare to the sharp `bolt_closed_volume`; `tests/test_solid.py:200-208, 527-533, 597-603` do the same. - **A required `head_chamfer` in the model validator:** D-06 says direct construction is not refused.

## D-07: The analytic closed form (priority 1)

### Notation

`a = s/2`, `R = a / cos 30 deg = 2a/sqrt(3)`, `tau = tan(beta)`, `D` = depth cap (`k/2`), `rho` the radius. The removed volume is

`V = integral over [a, R] of arc(rho) * min(tau (rho - a), D) d rho`, with `arc(rho) = rho (2 pi - 12 acos(a/rho))` for `a < rho < R` (`hex_arc_inside`, `thread.py:588-599`).

### Antiderivatives (derived by parts, `w = sqrt(rho^2 - a^2)`, `A = acos(a/rho)`)

```
int rho^2 (2 pi - 12 A) d rho = 2 pi rho^3/3 - 4 rho^3 A + 2 a rho w + 2 a^3 asinh(w/a)
int rho   (2 pi - 12 A) d rho = pi rho^2 - 6 rho^2 A + 6 a w
```

(from `int rho^2 A = rho^3 A/3 - a rho w/6 - (a^3/6) asinh(w/a)` and `int rho A = rho^2 A/2 - a w/2`). Both vanish at `rho = a`. At `rho = R` (`A = pi/6`, `w = a/sqrt 3`): `I2(R) = a^2 (2 sqrt 3 - pi)`, which equals the hexagon area less the inscribed disc, a built-in check.

### Result

Uncapped (the cap never binds, `D >= (R - a) tau`):

```
V = tau * a^3 * K0,    K0 = 4/3 + pi/3 + ln 3 - 2 sqrt 3 = 0.015041558060286064
```

Capped (`D < (R - a) tau`): let `x = D / tau` (how far past the inscribed circle the cone reaches the cap), `rho_c = a + x`. Then

```
V = tau * J(rho_c) + D * (I2(R) - I2(rho_c)),     J(rho) = int_a^rho arc(r) (r - a) dr
```

with, writing `xi = x/a`, `ch = 1 + xi`, `w1 = sqrt(xi (xi + 2))` (that is `w/a`), `g = atan2(w1, 1)` (that is `acos(a/rho_c)`), `theta = asinh(w1)`:

```
J / a^3   = (pi/3) xi^2 (2 xi + 3)  -  2 [ ch^2 (2 ch - 3) g + w1 (3 - ch) - theta ]
I2 / a^2  = pi w1^2 - 6 ch^2 g + 6 w1
V         = tau a^3 (J/a^3) + D a^2 ((2 sqrt 3 - pi) - I2/a^2)
```

The `pi` part of `J` is exact and stable; only the bracket (the `acos` part) cancels three orders of magnitude at small `theta`. For `theta < 0.05` replace the bracket term by its series (exact rational coefficients, derived with `fractions` in scratch `series.py`):

```
-2 [ ... ] = - theta^5 (6/5 + theta^2 (1/2 + theta^2 (13/180 + theta^2 * 71/10080)))
```

The next term is `-1103/3931200 theta^13`, below 1e-14 relative at `theta = 0.05`.

### Verified implementation (scratch `closed_form2.py`, pure `math`)

```python
SQ3 = math.sqrt(3.0)
HEX_RIM = 2 * SQ3 - math.pi                                 # (hexagon - inscribed disc) / a^2
UNCAPPED_J = 4 / 3 + math.pi / 3 + math.log(3) - 2 * SQ3    # J(R) / a^3

def chamfer_volume(s, angle_deg, depth):
    if not 0 < angle_deg < 90:
        raise ValueError(f"angle {angle_deg:g} degrees must be above 0 and below 90")
    tau = math.tan(math.radians(angle_deg))
    if not (tau > 0 and math.isfinite(depth) and depth >= 0):
        raise ValueError("no honest volume")
    a = s / 2
    x = depth / tau                         # never form (a + x) - a
    if x >= a * (2 / SQ3 - 1):              # R - a: the cap never binds
        return tau * a**3 * UNCAPPED_J
    xi = x / a
    w = math.sqrt(xi * (xi + 2)); theta = math.asinh(w); gd = math.atan2(w, 1.0); ch = 1 + xi
    jpi = math.pi / 3 * xi * xi * (2 * xi + 3)
    if theta < 0.05:
        t2 = theta * theta
        jrat = -theta**5 * (6/5 + t2 * (1/2 + t2 * (13/180 + t2 * 71/10080)))
    else:
        jrat = -2 * (ch * ch * (2 * ch - 3) * gd + w * (3 - ch) - theta)
    i2 = math.pi * w * w - 6 * ch * ch * gd + 6 * w
    return tau * a**3 * (jpi + jrat) + depth * a**2 * (HEX_RIM - i2)
```

### Numerical pitfalls (all measured)

1. **First version (`rho_c = a + depth/tau`, `w = sqrt(rho_c^2 - a^2)`, `ln(rho_c + w)`)**: worst error 5.4e-6 at depth/full = 1e-9, rising as `1/x`; at beta = 89.99999999999999 it returned **-49.5 mm3** (a negative volume). Cause: rounding in `rho_c - a`, then three-order cancellation. The stable form above (`x` directly, `atan2`, `asinh`, series below `theta` 0.05) fixes both: beta 89.99999999999999 at depth 2.0 gives 16.1254 (reference 16.125...).
2. **beta = 0 / underflow:** `tan(radians(5e-324))` is 0.0, so `depth / tau` is a `ZeroDivisionError`, which is not a `ValueError`; `derive`'s row loop catches only `(OverflowError, ValueError)` (`calc/__init__.py:271-274`) and would 500. The function above raises `ValueError` first (`not tau > 0`). Callers must also skip beta = 0 (no cut, no term) per D-01.
3. **`acos(a/rho)` near `rho = a`:** use `atan2(w, a)` with `w = sqrt(x (x + 2a))`.
4. **Uncapped constant has cancellation ~2.4 digits** (0.015 against terms near 3.5): error about 2e-14, harmless.
5. **Uncapped branch speed:** about 0.17 microseconds per call against 7.0 ms for the 40 000-point numeric (uncapped branch only measured).

## Common Pitfalls

### Pitfall 1: Piece gate on the assembled bolt refuses valid small chamfers
**What goes wrong:** `T_PIECE` 0.03 of a 0.03 mm3 piece is 1e-3 mm3, near the whole-bolt volume noise (~5.5e-5 mm3 constant bias measured, rising with the shape's face count).
**How to avoid:** cut and gate the head prism before the fuse (measured above).
**Warning signs:** `wrong head chamfer ... relative error +1.7e-02` for beta about 0.1.

### Pitfall 2: Oracle returns a wrong number at extreme beta
**What goes wrong:** the naive `rho_c = a + depth/tan` form printed -49.5 mm3 at beta 89.99999999999999 and `derive` would print a plausible-looking volume (L02).
**How to avoid:** the stable form; test beta 89.99999999999999, 89.9999999, 1e-9 and depth/full 1e-12.

### Pitfall 3: `ZeroDivisionError` is not caught by `derive`
**What goes wrong:** `head_chamfer=5e-324` is accepted by the model and `tan` underflows to 0.
**How to avoid:** `ValueError` in the oracle (caught by the row loop, "volume not reported" warning); a test that `derive` and `build` both stay off a 500 (build gives a `BuildError`).

### Pitfall 4: `assemble` that silently chamfers breaks `bench/` and four tests
**What goes wrong:** `bench/end_cuts.py:309,322,388`, `bench/head_fuse.py:97`, `tests/test_solid.py:206,531,601` build `bolt.assemble(p, thread)` on a default `BoltParams` and compare to a sharp closed form.
**How to avoid:** keep `assemble` sharp by default; pass the chamfered head explicitly from `_build_bolt`. (Alternative: set `head_chamfer=0.0` in `BoltCase.params()` and `head_fuse.Case.params()`, more edits and it changes what bench probes mean.)

### Pitfall 5: `cut()` returns a Compound
**What goes wrong:** `bolt._solid(head.cut(...))` raises `Geometry kernel produced Compound for the head`.
**How to avoid:** keep the cut as a `cq.Shape`, `check_structure`, then fuse (what `nut.finish` does).

### Pitfall 6: The standing-warning wording appears in four test files
Update `tests/test_cli.py:23-25`, `tests/test_calc.py:56-58`, `tests/test_parity.py:417-419` and the constant in the same commit (D-12).

### Pitfall 7: Existing exact-warning tests meet the new cap warning
Any bolt test with `k < 0.0893 s` and default `head_chamfer` now carries one more warning (for example `s` at the 1e5 bound with default `k` 4). Run the suite and fix each by choosing realistic `k` or asserting the new warning.

def head_chamfer_conflict(s: float, k: float, angle_deg: float) -> str | None:
    if not all(math.isfinite(v) for v in (s, k, angle_deg)):
        return None
    if not (s > 0 and k > 0 and 0 < angle_deg < 90):
        return None
    full, _ = head_chamfer_depths(s, k, angle_deg)

    return (f"head_chamfer and k: head_chamfer {_plain(angle_deg)} degrees would cut {full:.4g} mm "

            "or raise k")
