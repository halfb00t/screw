## CX-01 (minor): the kernel bound divided by zero for a tiny head

- **Where:** `src/screw/calc/thread.py`, `head_chamfer_kernel_bound`.
- **Failure:** the model accepts `s = 1e-170`. `s * s` underflows to `0.0`, so `derive` raised
  `ZeroDivisionError`, and `GET /api/bolt/info?s=1e-170&d=1e-171&pitch=1e-172&length=1e-171`
  returned 500. With `head_chamfer=0` the same query returned 200.
- **Fix:** ad681d6 divides by `s` twice. The bound overflows to `inf`, and every angle falls below
  it, so the chamfer rows and the volume are withheld with the existing warning (L02).
- **Test:** `tests/test_api.py::test_a_head_so_small_its_width_squared_underflows_is_a_document_not_a_500`.

## CX-02 (minor): an unreadable s or k produced a conflict that quoted a value nobody sent

- **Where:** `src/screw/app.py`, `refuse_explicit_conflict`.
- **Failure:** a value `float()` could not read was dropped. The head_chamfer rule then read the
  dropped `s` or `k` from its frozen default (D-05). `?head_chamfer=80&s=abc` was a 422
  `head_chamfer_conflict` that quoted "at s 10 mm". The CLI was not affected, because argparse
  rejects `--s abc` first.
- **Fix:** 4a0d7c6 keeps the raw string. No rule judges a string, so the query model's 422 names
  the bad field.
- **Test:** `tests/test_api.py::test_an_unreadable_s_or_k_beside_a_deep_head_chamfer_is_its_field_422_not_the_conflict`
  (`s`, `k`).
