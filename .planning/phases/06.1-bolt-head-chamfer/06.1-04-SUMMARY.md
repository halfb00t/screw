# Phase 06.1 Plan 04: Request-boundary 422 for head_chamfer Summary

**An explicit `head_chamfer` whose model depth exceeds k / 2 is refused as 422 `head_chamfer_conflict` (fields head_chamfer, k) on the API and exit 2 on the CLI with the same sentence, judged at s and k from the request or the frozen defaults; a defaulted angle is still capped and warned.**

- **Completed:** 2026-10-24T12:22Z
- **Tasks:** 2 (tracer + auto, both tdd)

## Accomplishments

- `_bolt_explicit_conflict` now judges thread_length first (unchanged text and type), then head_chamfer. The early return that would have skipped a second rule is gone: the thread_length rule returns only when it finds a conflict.
- The head_chamfer rule needs only head_chamfer explicit; `s` and `k` come from `values` or from `BoltParams.model_fields[..].default`, narrowed with `isinstance(.., float)`. Preset-filled `s` and `k` count as given because the CLI expands `--preset` first.
- The threshold is the cap's (`head_chamfer_conflict`, plan 01, reads `head_chamfer_depths`), so no explicit angle builds a part that differs from its model. Tested at the equality (`k = 2 * depth` builds uncapped with `chamfer_depth` equal to k / 2) and one float below (`math.nextafter`) is a 422.
- The API `msg` and the CLI `error:` line are one sentence (parity test over angles 80, 30 with s 100, and 68.86).
- No catalogue row carries `head_chamfer`; `--preset iso4017:M6x20` keeps 30.0, a typed 15 stays 15.0, both stay an exact match (D-13).

## Open observation (from plan 03, weighed against this plan)

At `head_chamfer = 5e-324` the solid build is refused (BuildError, 422 `build_error`) while `derive()` reports `chamfer_depth` 0. This plan's boundary refusal does not cover it: `head_chamfer_conflict` judges only the depth against k / 2, and a depth of 0 is not over it, so the request passes the rule and reaches the model and the build, which refuses it by name. That is the behaviour D-18 specifies (a tiny angle builds or is refused as a named `BuildError`, never a 500 or a wrong number). No behaviour was added here.

Also noted: the page writes only fields that differ from their defaults (`partQuery`), so a typed 30 is never an explicit head_chamfer there; consistent with D-04, and documented in `_bolt_explicit_conflict`'s docstring.
