│   ├── iso261.py  iso965.py  iso4014.py  iso4017.py  iso4032.py   (iso4762.py in v2)
│   └── presets.py         # expand(preset_id) -> {field: mm}
├── solid/                 # only package that imports cadquery / OCP
│   ├── __init__.py        # build(), export(), _LOCK, solid cache, tessellation()
│   ├── helical.py         # helical_solid(section, length, pitch, hand) + postcondition

│   └── pair.py            # interference() with controls
├── pool.py  records.py  build_errors.py  app.py  cli.py

### Structure rationale

- **`calc/` and `solid/` become packages** because three kinds plus a thread would push spur's 1,191-line `calc.py` and 597-line `model.py` `[S]` past what one file holds well. Spur's own docs say "promote to a directory when it stops holding it" `[S http-api.md]`.
- **`tables/` is a leaf** so the preset can never become the source of truth by an import accident (contract 6).
- **`feasibility.py` is split from `derive.py`** because `params` validates by calling `check` (spur's lazy import in `_feasible` `[S params.py:169]`). If `check` lived beside code that reads tables, `params -> calc -> tables` would be an indirect path and contract 6 could not use `allow_indirect_imports = false`.
- **`helical.py` is separate from `bolt.py`/`nut.py`** so the one risky builder is unit-tested on a bare rod and a bare void, with the closed form, before any head, table or hex exists.

## Q1. One parameter model for several types

### What was tried, against the pinned stack `[V]`

| Option | Query params (API) | Schema -> form | Flags -> CLI | Verdict |
|--------|-------------------|----------------|--------------|---------|
| Discriminated union (`Annotated[Union[Bolt, Nut], Field(discriminator="type")]`) | **`AssertionError: Query parameter 'q' must be one of the supported types`** at route definition, fastapi 0.142.2 | `TypeAdapter(...).json_schema()` has keys `$defs`, `discriminator`, `oneOf` and **no top-level `properties`**; spur's form loop is `Object.entries(schema.properties)` `[S static/app.js:51]` | a union has no `model_fields`; spur's `_add_gear_args` iterates `GearParams.model_fields` `[S cli.py:44]` | Breaks all three front ends. Reject |
| One wide model, per-type validity | works (`?type=nut&m=7` accepted) | flat, but shows every type's fields unless the UI also learns per-type visibility | works | Mechanically fine, semantically wrong (below) |
| One model per type | works with `Query()` subclass | flat `properties` per type | works per subcommand | **Chosen** |

### Why not wide

1. **Silent partial success.** A bolt link carrying `m=5` (a nut field) would be accepted and ignored unless every irrelevant field is validated per type. That matrix grows with each type (socket cap adds head diameter, socket size, socket depth). Spur L03's line is "did the user ask for this?"; a field the user set must either matter or be refused.
2. **The cache key widens.** Defaults are equal, so it is harmless until a user sets one; then two links describing one nut occupy two cache entries and two builds.
3. **The UI needs per-type knowledge anyway** (hide irrelevant groups), so the wide model saves no front-end code, it only moves the knowledge out of the schema into JS.
4. Per-type models get the refusal for free: `extra="forbid"` on a `Query()` model returned `422` with `type: extra_forbidden, loc: ["query","m"]` for a stray `m` on a bolt `[V]`.

### What each front end enumerates

The registry `KINDS` is the only thing a front end iterates. That is what keeps "one model, three front ends" true when there are several models (L02 in spur's log: "a field added once shows up in all three").

- **API.** `GET /api/{kind}/info`, `GET /api/{kind}/model.{stl,step}`, `GET /api/schema?kind=`, `GET /api/kinds`. With three kinds, write the routes explicitly (two per kind, each five lines delegating to one `_serve()`), per AGENTS.md "three similar lines beat a premature abstraction". Generating routes in a loop would need a runtime-built annotation, which mypy `--strict` with `disallow_any_explicit` (L04) will not accept without `Any` or ignores. UNVERIFIED that no typed workaround exists; not worth finding for three kinds.
- **Extras per endpoint need a subclass, as in spur.** A `Query()` model cannot be mixed with another query parameter: declaring `q: Annotated[Bolt, Query()]` plus `quality: Query` makes OpenAPI list the model as a single parameter `q`; subclassing yields `['d','length','quality']` `[V]`. Spur's `ModelQuery(GearParams)` plus `_gear()` strip `[S app.py:227-244]` therefore reappears per kind. Keep it to a mixin and one generic strip helper:

```python
class _Quality(BaseModel):
    quality: Literal["preview", "fine"] = "fine"

class BoltModelQuery(BoltParams, _Quality): ...

def strip[T: FastenerParams](q: FastenerParams, cls: type[T]) -> T:
    # equality includes the class, so an unstripped query would never share a cache entry
    return cls(**q.model_dump(include=set(cls.model_fields)))
```

- **CLI.** `screw info bolt ...`, `screw export nut -o nut.step ...`. `_add_args(ap, model)` is spur's `_add_gear_args` taking the class as a parameter; one subparser per `KINDS` entry (a short loop is fine here, the parser is untyped argparse). **New:** `left_hand: bool` needs `argparse.BooleanOptionalAction`; spur's `type=field.annotation` path would pass `bool`, and `type=bool` turns the string `"false"` into `True` `[V]`.
- **UI.** The form fetches `api/schema?kind=<kind>` and a kind selector reads `api/kinds`. **New:** spur's control builder handles only `enum` and numbers `[S static/app.js:64-74]`; a boolean field needs a checkbox branch. The shareable link is the URL **hash**, written with only non-default fields `[S static/app.js:95-107]`; it gains `kind=` (omitted means `bolt`, frozen forever by L05, so links never re-point when a kind is added).

### Shared base and defaults

```python
class FastenerParams(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")
    d: float         # nominal major diameter, mm      (default 6.0, absolute, L05)
    pitch: float     # mm                              (default 1.0)
    left_hand: bool  # default False
```

`BoltParams` and `NutParams` default to the same `d` and `pitch`, so **a default bolt and a default nut are a pair**. That is a test (`defaults mate`), and it is the strongest regression guard for L05 in this product: if either default ever moves, the test fails before an old link silently rebuilds a different part. `clearance` lives on `NutParams` only (PROJECT.md). Field lists belong to the requirements phase, not here.

Pydantic `frozen=True` gives `__hash__`; **hash and equality both distinguish classes** (`hash(Bolt(d=6)) != hash(Nut(d=6))`, `Bolt(d=6) == Nut(d=6)` is `False`) `[V]`, so spur's pool affinity (`hash(p) % workers` `[S pool.py:97]`), the bytes cache and the solid `lru_cache` keep working unchanged across kinds. Preview, STL and STEP for one part still land on one worker.

## Q2. Tables, presets and per-row verification

### Where tables live

`src/screw/tables/`, typed Python, not JSON/CSV: mypy `--strict` checks every row's shape, import-linter can wall the package, there is no runtime file I/O, and `disallow_any_explicit` (L04) is satisfied. One module per standard.

```python
@dataclass(frozen=True)
class Source:
    standard: str      # "ISO 4017"
    edition: str       # "2022"            <- confirm in the tables phase, PROJECT.md says numbers are from memory
    clause: str        # "Table 1, M6 row" <- required: no default
```

A row type has `source: Source` with no default, so **a row without a citation does not type-check**, which turns PROJECT.md's "a row without a cited source does not ship" into a gate failure. A second test asserts `clause` is non-empty and that row ids are unique.

### How a preset fills mm fields without becoming truth

```
tables.presets.expand("iso4017:M6x20")  ->  {"d": 6.0, "pitch": 1.0, "length": 20.0, "s": 10.0, ...}   # pure, kernel-free
```

- **UI:** picker calls `GET /api/preset?...` (pure maths, serving process), writes the returned mm into the form inputs; from there the normal `info`/`model` flow runs and the hash link carries only mm fields that differ from defaults `[S static/app.js:101-107]`. The preset id is never serialised.
- **CLI:** `--preset iso4017:M6x20` is expanded to field values *before* the model is built; explicit flags override. `cli` may import `tables` (contract 7 only forbids the reverse).
- **API:** query takes mm only. No `preset` parameter exists. `/api/preset` is a helper that returns a dict.
- **Invariants, each enforceable:** no model has a field named `preset`, `size` or `standard` (test over `KINDS`); contract 6 (params cannot import tables); a "matches row" annotation on the info panel is computed in `derive`, which may read tables, and can only *report* agreement, never alter a build.

### Per-row verification

Parametrise by iterating the table so a row cannot be added without its tests (`id = f"{standard}:{size}"`). What a row test can honestly assert:

1. Citation present (type + test).
2. Relations the standard itself states (for example `s_min <= s_max`, across-corners vs across-flats within the standard's own bounds, `b` vs `L` consistency). **A row test checks relations, not transcription.** Transcription correctness stays a human check; for about 14 sizes, double-entry (a second independent transcription diffed by test) is cheap if the owner wants stronger assurance. State this limit in the docs rather than implying more.
3. `expand(row)` validates under the model and `derive()` echoes the row's numbers (round trip).
4. Kernel build: valid, one solid, volume against the closed form. Cheap with a good construction (`[M]`, build plus trim: 0.5 to 3.4 s for twist-built bolts, 1.8 to 14.7 s for ruled, M2 to M20 spot sizes), so it fits the gate only after the spike measures the grid (PITFALLS C11).
5. Pair proof for nut rows: **slow tier** (Q3).

## Q3. Proving a mating pair in the kernel

### What was measured `[M]`

Twist-built bolt (exact section, ISO 68-1 basic profile, one start), nut = hex prism minus the matching helical void grown radially by `c`, nut placed on the bolt, `common(bolt, nut)`:

| Size, nut height | Pose | c = 0.15 | c = 0.05 | c = 0 (coincident flanks) | c = -0.05 |
|------------------|------|----------|----------|---------------------------|-----------|
| M6, 5 mm | matched phase (z0 = k x pitch) | 0 (4.2 s) | 0 (7.7 s) | 0 (8.6 s) | 3.36 mm3 (7.3 s) |
| M6, 5 mm | half-pitch off (must collide) | 10.0 | 13.6 | **0 at two of three slides, 15.5 at one** | **0 at two of three slides, 17.5 at one** |
| M20, 16 mm | matched | 0 (12.0 s) | 0 (13.6 s) | not run | not run |
| M20, 16 mm | half-pitch off | 361 (3.3 s) | 404 (3.2 s) | not run | not run |
| M2, 1.6 mm | matched | 0 (1.3 s) | 0 (5.4 s) | not run | not run |
| M2, 1.6 mm | half-pitch off | 0.139 (1.5 s) | 0.456 (1.2 s) | not run | not run |

Reading:

1. **A zero is the answer a broken boolean gives.** At clearance <= 0 the same physical collision (half-pitch offset, identical by helical symmetry) returned an empty intersect at two nut positions and 15.5 mm3 at a third; no exception, no warning. A `cut`-based formulation failed differently (a *false positive* of 85.9 mm3 on a correct matched pose at c = 0). OCCT's own documentation says an empty compound can come back with no errors or warnings dumped `[W]` (LOW), which matches. At clearance >= 0.05, 12 of 12 poses across three sizes were right. 12 poses is not a reliability proof; it is why controls, not trust, must be the design.
2. **The pose is part of the check.** A thread pair is invariant under *screwing* (rotation and translation together), not under pure axial slide: sliding the nut by half a pitch is a half-turn phase error and collides by design. So the check must place the nut at an integer number of pitches, and a half-pitch slide is a free positive control that needs no negative clearance. (PITFALLS C4 item 2 words this as invariance under axial slide; the measurement says the opposite, and it matters for how the fixture is written.)
3. **Cost, `[M]`, one machine:** 1.2 to 13.6 s per intersect; the *passing* (empty-result) case is the slow one. M20 with a 16 mm nut at a non-matching phase measured 17 to 33 s in an earlier pose. A planar-slab alternative (17 thin slabs per pair) was consistent with symmetry but cost 12 to 16 s, 201 s at c = 0, and is not worth adopting.
4. Volumes above are default `Volume()`. PITFALLS C2 shows that can be off by up to 20% on helical B-spline faces; use the precision-controlled form or mesh volume in the real check. For zero versus non-zero the decision is "does the result have faces", which does not depend on the estimator, but the *magnitude* used in a control must.

### Recommended design

```python
@dataclass(frozen=True)
class PairReport:
    verdict: Literal["proven", "violated", "inconclusive"]
    interference_mm3: float          # the pair as given
    control_mm3: float               # same pair, nut slid half a pitch; must be > floor
    clearance: float
    engaged_length: float
```

- Lives in `solid/pair.py`; it **builds both parts with the same `solid.build` the product ships**, never a test-only builder, so what is proven is what is downloaded.
- Algorithm: (a) maths pre-check from `calc/thread.py` (same `d`, `pitch`, hand; clearance > 0; minimum radial gap from the closed form is >= `c`), no kernel; (b) kernel `common` at integer-pitch pose; (c) control: half-pitch slide, must exceed a floor derived from the closed form; (d) verdict is `proven` only if (b) is empty **and** (c) fired; an empty (c) is `inconclusive`, never a pass. Clearance <= 0 returns `inconclusive` by construction (coincident flanks), with an analytic statement instead (PITFALLS C4 item 3).
- Also run: a left-hand pair, and a mixed-hand pair that must report `violated` (PITFALLS C4 item 4).

## Q4. Thread geometry as a component

### Split

| Concern | Lives in | Why there |
|---------|----------|-----------|
| ISO 68-1 basic profile from `(d, pitch)`: H = (sqrt(3)/2) P, crest and root flats, `d1`, `d3`, flank angle | `calc/thread.py` | pure arithmetic, runs on every keystroke, kernel-free (contract 2). Numeric coefficients are from memory here: confirm against the standard in the tables phase (PROJECT.md caveat) |
| Closed-form cross-section area `A = (pi/P) * integral r(u)^2 du` over one pitch, flank gaps, turns | `calc/thread.py` | the **oracle** the solid is tested against; the same philosophy as spur L33 (closed-form proof beside the kernel) |
| `ThreadSection`: the radial profile as a list of `(u, r)` vertices over one pitch, plus hand | `calc/thread.py` (a frozen dataclass of floats) | kernel-neutral hand-off between maths and sweep |
| Turning a section into a helical solid | `solid/helical.py` | the only code that knows which OCCT construction is used |
| Head, shank, thread/shank junction, end chamfer envelope | `solid/bolt.py` | per-kind |
| Hex blank, minus the helical void | `solid/nut.py` | per-kind |

### One builder for both parts

An external thread and an internal thread are the same helical solid with different sections: the bolt's section is the bolt's profile; the nut's *void* is a section whose "crest" is the nut root. So:

```python
rod  = helical_solid(external_section(d, P, c=0.0),  length, hand)     # bolt thread
void = helical_solid(internal_void_section(d, P, c), length + 2*P, hand)  # nut thread void, grown by c
nut  = hex_blank(...).cut(void.translated(-P))
```

- **Handedness** is the sign of the twist plus a mirrored section phase. Verified for one size `[V]`: the left-hand rod had the same volume as the right-hand one (454.563 against 454.564 mm3) and the common volume of the left-hand rod with the mirror of the right-hand rod equalled its own volume, i.e. they are the same solid. One size only; the spike covers the grid and a mixed-hand pair (PITFALLS M2).
- **Length and runout.** Do not build the shank thread-then-hide it. Build `helical_solid(length = thread_length)` only, and fuse it to the plain shank at a **planar** interface; a union that overlaps the thread crest cylinder is a coincident-surface boolean (the most fragile kind). This also makes cost scale with thread length `b` (ISO 4014) rather than overall `L`. The end chamfer is one boolean: intersect with a revolved envelope. Measured trim cost `[M]`: 0.4 to 1.1 s for twist at M2 to M10 and 0.13 to 0.3 s for ruled/sweep, 3.2 s for a long fine twist rod (M3 x 40), 70 s for one failing sweep.
- **Turn cap.** Build cost and failure both depend on turns (`L/P`), not diameter (PITFALLS C3). The model needs an `le` on thread length that is a measured constant of the form `HEX_CELL_CAP` was in spur (measured by a probe before any field exists). I do not propose a value: see the evidence table, where the failing frontier is not monotone.

### Postcondition on every thread build

Every `helical_solid` result must pass, or `BuildError` is raised (the module's documented contract, `[S app.py:476-482]`: `BuildError` is the only exception the module lets out):

1. `isValid()`;
2. exactly one solid;
3. volume (precision-controlled or mesh-based, PITFALLS C2) equal to the closed form within a measured tolerance.

Why it is not optional `[M]`: two of three constructions produced **valid, single-solid, wrong** results in the grid below (a plain `fuse` of a swept tooth with its core silently returned only the tooth: 90.74 mm3 against 459 expected; `tol=1e-4` or a core shrunk by 0.02 mm fixed it). An `isValid()`-only gate would have shipped them. Note the shrunk-core remedy itself moves the root radius, so it is a geometry change, not a free fix; the postcondition must compare against the closed form *including* it, or the construction that needs the shrink is disqualified.

## Q5. STEP and STL

### STEP

- **Modelled thread, same solid as STL, one code path.** The product is a precise STEP solid with a real thread (PROJECT.md); a cosmetic thread cannot be written by `exportStep`, and OCCT's writer emitting cosmetic-thread PMI is UNVERIFIED. Forum reports (`[W]`, LOW) say STEP files do not carry cosmetic-thread information and that threaded holes re-import as plain holes in other CAD; modelled threads survive as geometry. So "cosmetic in STEP" is not a missing feature to add; it is not what a STEP carries.
- **Downstream CAD behaviour is UNVERIFIED** beyond OCCT itself. Expectation to test, not assume: other CAD imports the thread as bare B-spline faces with no thread feature recognition and may be slow on long ones.
- **What round-trips `[V]`:** `exportStep` then `importers.importStep` on a trimmed M6 x 20 gave the same face count (8 to 8 and 30 to 30), `isValid()` true, one solid, and volume within 0.007% (twist) and 0.0003% (ruled); file schema `AUTOMOTIVE_DESIGN { 1 0 10303 214 1 1 1 1 }` (AP214). Make this a test: STEP round-trip volume against the closed form.
- **Size `[M]`:** 0.7 to 0.9 MB raw for M6 x 20 (about 25% after gzip), up to 3 MB at M20 x 200 (ruled). PITFALLS C9 reports superlinear growth in turns (48 MB at 160 turns). STEP is small beside STL at the sizes in scope.

Implications, each mapped to a spur decision that does **not** carry:

1. **Mesh time, not build time, is the bound.** In spur, `export(p, fmt, quality)` runs build and mesh in the worker under one timeout `[S pool.py:53-67]`. For threads the mesh is up to 30 s of the budget while the build is 0.1 to 14 s. Spur's `TESSELLATION = {"preview": (0.08, 0.5), "fine": (0.01, 0.1)}` `[S model.py:53]` is an absolute deviation chosen for gears: 0.08 mm is 20% of an M2 pitch of 0.4. Replace with a `tessellation(params, quality)` function whose deviation is a fraction of the thread depth (PITFALLS C9), picked from a measured deviation-versus-triangles curve, and capped by a triangle budget.
2. **The bytes cache silently drops big entries.** `_BlobCache.put` returns without storing when `len(data) > budget` `[S app.py:73-74]`, and spur's budget is 64 MB with two encodings per entry `[S app.py:88]`. A 61 MB raw STL is rebuilt on every request and never cached, with no signal. The cap on thread length must be derived so that the largest allowed payload, in both encodings, fits the budget; otherwise a cache that looks configured is a no-op.
3. **gzip level (L19) must be re-run.** Its rule was "adopt a higher level only if >=10% smaller and <=1.5x wall" `[S app.py:180-182]`; at 54% the redundancy picture differs. Re-run `export_cost` on a threaded corpus, do not carry level 1.
4. **Memory ceiling (L17) must be re-swept.** A kernel-free parent plus N workers was measured for gears `[S overview.md]`. The 1 GB mesh transient on one construction is 24x the other here. The solid cache holds solids (BSpline-heavy for threads) and the mesh is built on a copy (L24), which still allocates.
5. **L24 carries and matters more.** Exporting one shape at three tolerances in sequence reused the finest mesh (PITFALLS C9, `[M]` there); keep "a cached solid never carries a mesh: STL export meshes a copy" `[S L24]`, and add watertightness and mesh-volume-versus-closed-form checks.
6. The UI preview must not depend on the fine mesh; preview quality is a viewer concern only, and no printed number is computed from it.

## Patterns to Follow

### Pattern 1: Maths is the oracle, the kernel is the claim
**What:** every kernel result is checked against a closed form computed in kernel-free `calc`. **When:** every thread build, every table row build, every info-panel number that comes from the solid. **Trade-off:** you write the closed form first; that is the point (spur L33). **Example:** the section-area integral reproduced the twist rod volume to 0.0003% `[M]`.

### Pattern 2: Two independent formulations, plus a control that must fire
**What:** a proof that can return only "empty" is a proof of nothing. **When:** the pair check, and any other boolean whose success looks like absence. **Example:** half-pitch slide must collide; verdict `proven` requires it.

### Pattern 3: Registry-driven front ends with a model-driven parity test
```python
@pytest.mark.parametrize("kind", KINDS)
def test_front_ends_match_the_model(kind):
    fields = set(KINDS[kind].model_fields)
    assert cli_flags(kind) == fields | {"--preset"}                    # CLI
    assert api_query_params(kind) == fields | {"quality"}              # /openapi.json
    assert ui_form_fields(kind) == set(schema(kind)["properties"])     # /api/schema?kind=
```
Parity is proven by iterating the registry, not by hand; a new kind is covered the moment it is registered.

### Pattern 4: Cap-and-warn versus refuse, applied to threads
**What:** trim only what does not contradict an explicit choice (a chamfer larger than the thread depth is capped and warned); refuse a direct conflict (thread length above the bolt length, pitch not matching a requested standard row) with a `422` naming the fields (L02, spur L03). **Why here:** PITFALLS M4 (4014 thread length longer than the bolt).

### Pattern 5: One serving function, thin routes
`_serve(params, fmt, quality, request, backend)` is spur's 90-line `model()` body `[S app.py:381-499]` lifted unchanged; per-kind routes strip their query subclass and call it. The admission slot, gzip-in-slot (L19), error mapping (`BuildError` to 422, `BuildTimeout` and `BrokenProcessPool` to 503) stay in one place.

## Data Flow

### Request flow (preview, STL, STEP for one part)

```
UI keystroke
   -> GET /api/<kind>/info?mm...        serving process: params -> calc.derive (kernel-free)  -> JSON
UI debounce
   -> GET /api/<kind>/model.stl?...&quality=preview
        params = strip(query)                          # class-correct, cache-correct
        key = (params, fmt, quality, encoding)         # bytes cache in the PARENT
        hit  -> bytes
        miss -> admission slot (503 + Retry-After if full)
                 pool.executor_for(params) = executors[hash(params) % N]
                 worker: solid.export(params, fmt, quality)
                    dispatch on type(params) -> solid cache (lru on params)
                    build -> postcondition (valid, 1 solid, closed-form volume)
                    STL: mesh a COPY (L24) at tessellation(params, quality)
                    STEP: exportStep (no mesh attached)
                 parent: gzip inside the slot (L19), cache identity + gzip
```

### Preset flow

```
picker -> GET /api/preset?... -> tables.presets.expand -> {mm fields}
       -> form inputs set -> hash link carries mm that differ from defaults
CLI: --preset id -> expand -> flags -> FastenerParams(**mm)   (explicit flags win)
The preset id is never stored, never in a link, never in a model.
```

### Pair-proof flow (offline)

```
tests / `screw pair`
   -> calc.thread pre-check (same d, pitch, hand; c > 0; closed-form gap)
   -> solid.build(BoltParams), solid.build(NutParams)       # the shipped builders
   -> place nut at integer pitches; common(bolt, nut)
   -> control: slide half a pitch; common must be non-empty
   -> PairReport(verdict, interference, control, clearance, engaged_length)
```

### Key data flows

1. **Truth flows one way:** mm fields -> model -> maths -> solid. Tables flow into mm fields at the edge and never past `params`.
2. **Numbers on the panel come from `calc`, never from the mesh or the unchecked solid** (L08; PITFALLS C2 and C9).
3. **Errors are classified once:** parameter conflict is `422` from validation; kernel failure is `BuildError` -> `422`; timeout and worker loss are `503` (spur's error mapping, `[S app.py:430-466]`).

## Scaling Considerations

This is a self-hosted tool plus a possible public instance; the question is what breaks first, not user counts.

| Concern | One user / CLI | Several concurrent web users |
|---------|----------------|------------------------------|
| Per-build timeout | covers build **and mesh**; bound cites the worst allowed configuration, which is not the biggest bolt (PITFALLS C3) | unchanged; a timed-out worker is terminated and replaced `[S pool.py]` |
| Bytes cache | derived: largest allowed payload x 2 encodings <= budget, else cache is a silent no-op | same |

**First bottleneck:** mesh time and size on long, fine-pitch threads, not CPU on the build. **Second:** worker RSS under fine meshing, which sets the worker count.

## Anti-Patterns

### Anti-Pattern 1: A discriminated union as the one model
**What people do:** `Annotated[Union[Bolt, Nut], Field(discriminator="type")]` to get "one model". **Why it is wrong:** FastAPI rejects it as a `Query()` model, the schema loses `properties` (form breaks), and a union has no fields to generate flags from `[V]`. **Instead:** one model per kind, a registry, `kind` in the path.

### Anti-Pattern 2: A preset id in the model, the link, or the cache key
**Why it is wrong:** the link stops being able to rebuild the part without the table; editing one field after a preset leaves a stale id. **Instead:** the picker writes mm, nothing else survives; contract 6 and a no-`preset`-field test.

### Anti-Pattern 3: `assert interference == 0` at one pose
**Why it is wrong:** zero is what a failed boolean returns `[M]`. **Instead:** controls and verdicts (Q3).

### Anti-Pattern 4: Trusting `isValid()` or default `Volume()` on a thread
**Why it is wrong:** valid, single-solid, wrong results occurred in two of three constructions; `Volume()` is off by up to 20% on some (PITFALLS C2). **Instead:** the postcondition against the closed form.

### Anti-Pattern 5: Carrying spur's numbers
Timeout 30 s, `TESSELLATION`, gzip level 1, 64 MB cache, 358 MiB-class memory figures, `SPUR_SOLID_CACHE=4` are gear measurements. L07 already says so; the new fact is that the spread between constructions (15x triangles, 24x RSS) exceeds spur's whole range of gears.

### Anti-Pattern 6: Guessing a thread length by extrapolating from M6 x 20
The failing frontier was not monotone in turns `[M]` (80 turns failed at M20 and passed at M3; 60 turns passed at M20; 100 turns failed at M6). Bound the grid by sweeping it.

### Anti-Pattern 7: Hiding the thread under a shank cylinder
A union against a cylinder at the crest radius is a coincident-surface boolean. Build the thread only over `b` and fuse at a planar face.
