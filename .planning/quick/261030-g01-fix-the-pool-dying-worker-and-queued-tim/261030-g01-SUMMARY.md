## Measurement

Scratch script `g01_measure.py` (session scratchpad, not committed): a fresh `BuildPool(1, ...)`
with `tests/` on `sys.path` as pytest puts it, so the worker unpickles `test_pool._die` as the
tests make it. Host: 18 CPUs, macOS arm64. Load: `pytest -n auto --no-cov
--ignore=tests/test_pool.py`, one or two runs at once, six rounds in all.

| Reading | Alone (n=5, load 4.5-5.0), median / max | Under load (n=81, load 5.4-74.8), median / max |
| --- | --- | --- |
| `_die` to a cold worker, to `BrokenProcessPool` | 1.56 / 1.58 s | 1.94 / 9.25 s |
| Spawn + `_warm` + `os.getpid` | 1.43 / 1.45 s | 1.75 / 11.40 s |
| First `test_pool` function after an `os.getpid` warm-up (in-worker import of `test_pool`) | 0.10 / 0.10 s | 0.12 / 0.62 s |
| Queued test, first request (1.2 s build, deadline 2.0 s), `os.getpid` warm-up | 1.30 / 1.31 s | 1.33 / 1.997 s |
| Queued test, second request (deadline 4.0 s) | 2.51 / 2.51 s | 2.53 / 3.20 s |
| `_die` on a worker that has imported `test_pool` | 0.007 / 0.009 s | 0.011 / 0.027 s |
| Queued first / second after a `_sleep_past_timeout(0.0)` warm-up (n=33) | -- | 1.206 / 1.220 s; 2.411 / 2.425 s |

Findings:
- Dying-worker tests: the debt item's ASSUMPTION held. 13 of 81 cold `_die` samples overran 5 s.
- Queued test: a different cause. Its `os.getpid` warm-up loaded the kernel, not `test_pool`, so
  the worker imported `test_pool` (screw.app, fastapi) inside the first request's clock: up to
  0.62 s of 0.8 s slack, one sample 3 ms short of the deadline.
- No product bug: production's initializer `screw.pool._warm` imports `screw.pool` and
  `screw.solid` before the first `build_export`.

## Fix

`_start_worker(pool, params)` in tests/test_pool.py submits `_sleep_past_timeout(0.0)` and waits,
before the timed part; the three tests call it. Timeouts unchanged (5 s; 1.2 s under 2.0 s).
